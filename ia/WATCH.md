# WATCH.md — redistricting watch calendar

The one place the dates live: *when to look* for boundary and roster changes in this
instance's sources. The repo's `docs/REDISTRICTING_RUNBOOK.md` is *what to do* when a
boundary changes. Update the "Last done" column each time you complete a row — a
checkpoint with a stale date is a checkpoint that didn't happen.

---

## Per-decade — the census redistricting cycle

| When | What | Last done |
|---|---|---|
| After each decennial census (next: 2031–2032) | Congressional + legislative districts redraw: re-run `ia/scripts/build_legislative_boundaries.py` (all three targets — see its docstring for why the default differs from Wisconsin's), confirm the district counts against the apportioned delegation and the 50/100 chambers, and re-verify the smoke anchors against the rebuilt geometry | 2026-08-27 (all three built at 100.00% agreement) |
| Mid-decade — Iowa specifically | County-level SUPERVISOR districts move off the census cycle under Iowa's own law: **Senate File 75** (signed 2025-04-11) forced Story, Johnson and Black Hawk counties from at-large to district elections for November 2026. `ia/scripts/build_ia_supervisor_districts.py` pins the state aggregate's vintage (`LSA_LAST_EDIT_MS` = 2024-01-30) and refuses to build silently if it ever moves — re-run the builder and re-verify all three counties' PLANTYPE the day that check fires, not just the three named here | 2026-08-26 (Black Hawk shipped real geometry from its own hosted GIS; Story and Johnson shipped as county-level TRANSITIONING placeholders, both SOS-approved but no GIS service found for either) |
| Iowa specifically, no fixed cadence | Story's and Johnson's `TRANSITIONING` placeholders are the layer's known incompleteness, not a permanent design: re-check both counties' own sites (and a fresh ArcGIS org sweep, the Black Hawk precedent) periodically for a published district-map GIS service, which would let a future build replace the county-level fallback with real sub-district geometry the same way Black Hawk's was found | 2026-08-27 (first build; both still PDF-only) |
| Iowa specifically, no fixed cadence | Jones County is entirely absent from the state's own CountySupervisorDistricts aggregate (measured by name and by FIPS 105) — re-check on each vintage change (see the row above) whether the state has added it, and separately whether the county's own vector PDF map (`jonescountyiowa.gov/files/board_of_supervisors/bos_districts_final_23073.pdf`) is worth a Jackson-County-IL-style extraction | 2026-08-27 (first build; recorded as a coverage-gaps.json gap) |
| Iowa specifically, no fixed cadence | `county-subdivision` is live-fetched (no builder script, no committed data/app file — `ia/index.html`'s `tigerStatewideLoader`), so TIGERweb's own vintage bumps (this layer's metadata reads "January 1, 2025 vintage" as of this build) reach the app with nothing to rebuild. What CAN silently go stale is the card's three-way type classification (`township`/`city`/`ut`, read from `LSADC` via the NAME-minus-BASENAME suffix) — periodically re-run the tally query (`WHERE STATE='19'`, group by `LSADC`) and confirm it still returns exactly the three values this build measured (44 ×1,600, 25 ×62, 46 ×1); a fourth value would render with no Type row rather than break, which is safe but worth a look | 2026-08-27 (first build; 1,663 records, 3 LSADC values) |
| Iowa specifically, no fixed cadence | `municipality` is likewise live-fetched (same `tigerStatewideLoader`) with nothing to rebuild — new incorporations/dissolutions reach the app automatically. Nothing to classify (its `LSADC` is uniformly 25 — measured 2026-08-27), so unlike `county-subdivision` there is no derived value that can drift; if a periodic re-check ever turns up a second `LSADC` value, that is the signal Iowa has grown a second incorporated-place class and the card would need one | 2026-08-27 (first build; 939 records, 1 LSADC value) |
| Iowa specifically, per school year (consolidations effective each July 1) | School districts consolidate independently of any census: TIGERweb's `School/MapServer/0` (325 as of this build) already trailed the Dept. of Education's own current layer by one district — Orient-Macksburg dissolved into Nodaway Valley for 2026-2027, and TIGERweb's federal vintage hadn't caught up when this shipped. `ia/scripts/build_ia_school_districts.py`'s `DISSOLVED_INTO`/`EXPECT_TIGER`/`EXPECT_DE` constants gate on the counts it knows about and fail loudly the day either source's count moves again — re-derive the reconciliation (which district, into which neighbor) the same way this one was found: diff the DE org's newest and previous school-year-versioned layers (`IowaSchoolDistricts<YYYY>_<YYYY+1>`) by name, then spatially sample the dissolved district's old boundary against the new layer | 2026-08-27 (first build; DE layers for 2026-2027 and 2025-2026 both fetched and diffed the same day) |
| Iowa specifically, no fixed cadence | `zip-code` and `post-office` are both live-fetched by an Iowa bounding envelope, no builder script and nothing to rebuild — new ZCTAs and post offices reach the app automatically. Neither carries a derived classification that can drift (no `LSADC`-style field this app reads), and neither is a fixed count to gate on (envelope queries move as ZCTA boundaries and post offices near the state line change) — this row exists only so both live-fetched sources are on record, not because either needs periodic re-checking | 2026-08-27 (first build; 1,443 ZCTAs and 1,170 post offices measured in-envelope) |
| Iowa specifically, no fixed cadence | `police-station` and `fire-station` (phase 2 PR 1) are the same live-fetched-by-envelope shape as `zip-code`/`post-office` — no builder script, nothing to rebuild, no derived classification, envelope counts that legitimately move as USGS's structures dataset updates. The dataset is known (from Wisconsin's own build) to carry occasional stale/ghost records (a defunct department not yet removed) — the card's "nearest stations" framing is a proximity fact, never a jurisdictional claim, precisely so a ghost record degrades gracefully rather than misleading | 2026-08-28 (phase 2 PR 1; 449 police points and 1,262 fire points measured in-envelope, correcting the phase-2 roadmap's original 53/51 estimate) |
| Iowa specifically, no fixed cadence | `school-site` (phase 2 PR 3) is pre-built, not live-fetched — new/closed school buildings reach the app only on the next operator rebuild. Re-run `ia/scripts/build_ia_school_sites.py` periodically (no fixed cadence measured yet; DPI directories elsewhere in the fleet rotate roughly per school year) and watch for the naming trap the builder's own docstring records: the correct layer slug is `IowaSchoolBldgs`, never its internal title `PublicSchoolBldgs`, which names a different, stale 2018 service | 2026-08-28 (first build; 1,321 sites, all public, no placeless rows) |
| Iowa specifically, per-election (precincts move when a county re-precincts, most often after a redistricting cycle or a consolidation) | `precinct` (phase 2 PR 4) is pre-built from the same Legislature ArcGIS org and vintage (2024-01-30) as `county-supervisor` — re-run `ia/scripts/build_ia_precincts.py` on the same cadence you'd re-check that layer, and pin the item id (`d394edea208c4003ac1d6bd1ec78532f`) rather than a name-based search: two decoy services (`IaPrecincts` on the separate LSAFiscal org, a bare `Precincts` on the same org) sit at deceptively similar names. Re-verify the 2-record `PctNameOfficial` name gap (Warren County) hasn't grown, and never add `PollingPlace`/`PollingPlaceAddr`/`PPID` to `OUT_FIELDS` without first writing the display contract `docs/IA_EXPANSION_PLAN.md`'s phase 4 defers | 2026-08-28 (first build; 1,660 precincts, 99.95% point-agreement, 0 overlaps) |
| Iowa specifically, statutorily up to once per decade (Iowa Code SS602.6107 requires a Supreme Court review "beginning January 1, 2012, and at least every ten years thereafter"; no reorganization found enacted as of this build) | `ia-judicial-district` (phase 2 PR 5) is the one Iowa layer whose OWN weekly workflow re-verifies its geometry, not just its roster: `update-ia-judicial-district-roster.yml` runs `ia/scripts/build_ia_judicial_district.py --check` before every scrape, which re-fetches the LSAFiscal organization's own published district polygons and re-proves all 99 counties' crosswalk assignments against them — a moved county or a redrawn district fails that step loudly rather than drifting silently. If it ever fails, re-derive the crosswalk the same way this build did: iowacourts.gov's own per-district "District N Counties" page, cross-checked against Ballotpedia, both cited in the builder's own docstring | 2026-08-28 (first build; 99/99 counties spatially confirmed against the live LSAFiscal witness, 0 mismatches) |
| Iowa specifically, no fixed cadence (the Legislature's own ArcGIS org has already revised this boundary once, mid-2026, outside any obvious statutory cycle) | `community-college` (phase 2 PR 6) is pre-built, not live-fetched, and no weekly workflow re-checks it — re-run `ia/scripts/build_ia_community_colleges.py` periodically and watch its three build-time gates (15-name match against the CommColleges2020 witness layer, population summing to Iowa's exact 2020 census total 3,190,369, director-district count summing to 124): any one failing is the signal the source moved again. If Southeastern's own `NDISTRICT` ever reads anything other than 16, that specific assertion is this layer's redistricting tripwire. The deferred `cc-director-district` sub-layer is blocked on the LSA's `CC_DD2023` layer gaining Des Moines Area's missing District 2 polygon (confirmed absent 2026-08-28) — re-check that layer's per-college feature count against each college's own trustee count before attempting it | 2026-08-28 (first build; 15/15 colleges, all three witnesses exact) |

| Iowa specifically, per-election (all six county offices are elected on staggered four-year terms; supervisors turn over in halves) | `county` (phase 3 PR 1) now carries all six elected county offices, from FIVE publishers, and the thing to watch is not any one of them going down — it is the two DATED PDFs going stale while still answering 200. The ISSDA sheriff directory (April 2025) and the ICAA county-attorney roster (May 2026) are documents, not services: `ia/scripts/ia_county_officer_sources_scraper.py` pins each URL, so a NEW EDITION AT A NEW PATH looks exactly like no change at all. Re-check both associations' own pages for a newer file after each general election, and re-read the builder's divergence report — every line of it is a county where two publishers disagree, which is the earliest signal that one of them has stopped being maintained | 2026-08-28 (first build; recorder 99/99, sheriff 98/99, county attorney 97/99, treasurer 99/99, 92 of 99 boards) |
| Iowa specifically, no fixed cadence | The ISAC member portal is the ONLY statewide source for the county TREASURER and for the BOARD OF SUPERVISORS, and it is the one source here with no second witness for the treasurer at all. It is also measurably imperfect: it publishes an APPOINTED chief deputy in the elected sheriff's row in at least three counties (Crawford, Page, Sioux) and an appointed assistant in Page's county-attorney row — detected automatically by `build_ia_county_officers.py` only because each office's own directory names the same person as a deputy. **A mislabel in the treasurer's row would be invisible**, because nothing else publishes Iowa's county treasurers. If a treasurer directory ever appears (`iowatreasurers.org` is a payment portal today and names nobody), wiring it in closes the last unwitnessed office on this card | 2026-08-28 (first build; 4 mislabels detected and corrected, treasurer unwitnessed by construction) |
| Iowa specifically, per-election and on any board-size referendum | Seven counties ship NO board of supervisors, and the reason is a gate rather than a missing source: `build_ia_county_officers.py` refuses a board whose ISAC row count is not a legal 3 or 5 (Iowa Code 331.201) or that disagrees with the seat count read back from the shipped supervisor-district geometry. Adair (4), Floyd (2), Henry (4), Humboldt (6) and Tama (4) are impossible counts; Warren and Wright list a legal 5 against geometry seating 3. Re-check these seven on each refresh — a county genuinely moving from 3 to 5 members (Iowa Code 331.203 puts that to a referendum) would show up here first, and the fix is to rebuild the supervisor geometry, never to loosen the gate | 2026-08-28 (first build; 7 withheld, each with its reason on the card) |
| Iowa specifically, no fixed cadence | Five offices ship NO NAME because their two publishers name different people and no third witness resolved it (Davis sheriff, Sac→resolved, Henry and Keokuk county attorney, Humboldt and Jasper recorder). These are not errors to fix in code — they are two directories disagreeing, recorded on the card in those words. The way to close one is the way Sac's was closed: read the county's own office page, and add a `DIVERGENCE_RESOLVED` pin naming that page as the witness. The builder FAILS if a pin outlives the disagreement it settles, so the table cannot calcify | 2026-08-28 (first build; 5 withheld, 1 pinned) |


| Iowa specifically, per-election (supervisors serve staggered four-year terms, so roughly half of every board turns over each even year) | `county-supervisor` (phase 3 PR 2) now names WHO holds each district — but only for PLAN 3 counties, and only the ~17 of 40 that publish the pairing themselves. The thing to watch is not a county going down; it is the PROXIMITY RULE quietly losing its footing. The scraper reads no markup: it finds each known supervisor's surname and takes the nearest "District N" within 80 characters, which works because counties that publish this publish it adjacently (widest gap measured across 67 districts: **42 characters**). Every run prints its widest gap and flags any county above that measured maximum. **A run whose gaps creep toward the 80-character cap is the signal to re-measure rather than to widen the window** — Polk's page prints its five supervisors twice, once as a bare navigation run with no districts near it, and a window wide enough to reach from that run to an unrelated district mention would pair them confidently and wrongly | 2026-08-28 (first build; 17 counties, 67 districts, widest gap 42) |
| Iowa specifically, no fixed cadence | 23 of the 40 plan 3 counties ship NO keying, each with its reason in the scraper's own output: several refuse this client outright (403), two answer 202 behind a captcha — which is an access control this project does not route around — and the rest simply name no district on any page it can find. Those counties are not degraded: their supervisors are still named on the County card, unkeyed, which is the honest answer. Re-check them periodically; a county that redesigns its board page usually starts publishing the district as a side effect, and the scraper's link discovery is deliberately unpinned so it picks that up with no config edit | 2026-08-28 (first build; 23 skipped, every reason recorded) |
| Iowa specifically, on any board-size change or geometry rebuild | Two counties surfaced a conflict this pass rather than a gap, and both are worth re-reading whenever either side moves. **Humboldt**: ISAC lists 6 supervisors (illegal under Iowa Code 331.201), while the county's own page shows 5 districts and 5 of those 6 names — evidence the portal's 6 is the defect. **Warren**: the county's own page shows 5 districts and 5 names, but the shipped LSA geometry seats 3, so the keying is refused by the geometry gate and the likely stale party is the GEOMETRY, not the county. Warren is the opposite conclusion to Humboldt from the same shape of disagreement, which is exactly why neither is resolved by a rule | 2026-08-28 (first build; both refused, both recorded) |

## Grow this file

Every new layer ships with a row here naming when its source moves (school-year datasets
rotate every summer; county precinct files change per election; rosters change per election
and per resignation). A source with no row is a source nobody is watching.
