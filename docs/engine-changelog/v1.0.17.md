Fixes an adoption break in v1.0.16. **The engine bundle is byte-identical to v1.0.16** — same `sha256 13e3ffa0a213`, same 50+2 blocks, no JS change at all. What changes is the consume-side scripts the release also ships.

- **Changed `metro-worksheet.schema.json`**: `poi_geocode_bbox` is no longer in `required`. It stays a documented optional property.
- **Changed `generate_metro_files.py`**: `POI_GEOCODE_BBOX` falls back to `metro_bbox` when the worksheet doesn't declare `poi_geocode_bbox`, and the emitted comment says which case applies.

**What went wrong.** v1.0.16 introduced `poi_geocode_bbox` as a **required** worksheet key. The release ships the schema and generator as assets, so both sibling bump PRs picked up the new requirement against worksheets that had no such key, and their drift gate failed immediately and identically:

```
generate-metro-files: FAIL — worksheet does not validate against the schema:
  'poi_geocode_bbox' is a required property (at <root>)
```

Nothing was wrong with the engine bundle; the fan-out simply could not merge. Both bump PRs were closed and replaced by this release's.

**The rule this establishes: a new REQUIRED worksheet key is a breaking change for every fork, and the release pipeline will not catch it.** The CHI-side gates all passed — CHI's own worksheet had the key, so `generate_metro_files.py --check` was green, and the release job's self-checks build and apply the *bundle*, which never sees the worksheet. The break is only observable in a fork. So: **new worksheet keys are optional with a default that reproduces the old behaviour**, unless every fork's worksheet is updated in the same release. Where the default is genuinely the right answer — as here, since a fork whose layers are all city-scoped wants exactly `metro_bbox` — optional is not a compromise, it is the correct design.

Forks adopting this release get an emitted `POI_GEOCODE_BBOX` equal to their existing `METRO_BBOX` and therefore **no behaviour change**. The v1.0.16 guidance still stands and is still worth acting on: `poiGeocodeRequest` is fork-level code, and its bound belongs to the widest layer the fork ships, not to its metro. Set `poi_geocode_bbox` if and when a layer reaches past the metro.
