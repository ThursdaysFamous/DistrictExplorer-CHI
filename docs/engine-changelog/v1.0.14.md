Handoff 4 — the map hover popup, rebuilt on the card system (`docs/design_handoff_hover_popup/`, ids 9a/10a plus 10c's standalone block). The dark plate is retired: hover and click now speak the same visual language, so a hovered stack reads as a preview of the cards a click would open. Changed blocks only — **no new blocks, no fence-set change, no fork adoption required**.

- **Changed `styles-hover-responsive`**: the near-black popup plate is replaced by the card surface (white, `1px solid rgba(0,0,0,.08)`, radius 10, the card shadow, 324px content, white tip). Rows become a `10px 1fr` grid: the layer name is now the grey **label** (11.5/600/`#6b7280`) and the officeholder is the **primary line** (14/700/`#111827`) — the reverse of the old popup, where the colored layer name outranked the person and the tinted labels failed AA on near-black. New classes for the promoted pin header (`.hover-poi*`, `.hover-pin*`), the id pill (`.hover-pill`), the footnote (`.hover-foot`), and the pin's own-row accent (`.hover-row-own`). The `.hover-row-poi` rule and its CSS `📍` are gone — the card system carries no emoji.
- **Changed `hover-explorer`**: `hoverSnapshotHTML` (an HTML-string builder — the last one on this surface) becomes `hoverSnapshotNode`, building DOM through `cardEl` like every other card path. New helpers, all pure and local to the fence: `hoverRgb` / `hoverLuminance` / `hoverContrastOnWhite` / `hoverDotIsInvisible` / `hoverPillStyle` / `hoverTint` / `hoverDot` / `hoverPill` / `hoverPinGlyph` / `hoverPoiHeader`.
- **Changed `nearest-point-factory`**: the hover token gains `distanceLabel` — the same straight-line distance the card's row pill shows, measured from `state.selectedPoint` (null when no point is selected, so a pin never shows a distance from nowhere). This is the pill for a pin whose layer has no polygon row.
- Consume-side scripts are unchanged. No layer-contract change: `hoverName`, `hoverOfficial`, `pointOfInterest` and the `hoveredPoi` token all keep their current behavior and fields.

**Why the color math is in the engine.** On the old plate any palette color was legible; on the card surface the fleet's pale blues and near-whites are not. Rather than maintain a second, hand-picked popup palette per fork — which would drift from the map — `hoverPillStyle()` derives a printable pair from the same color the dot shows: it darkens the text toward black until it clears AA (4.5:1) on white, while the tint keeps the original hue, so the pill still reads as that layer's. `hoverDotIsInvisible()` swaps a near-white dot for a ringed one on the same luminance test. Both are WCAG relative luminance, so every fork's palette is handled by construction — CHI's `#3f9fd8` City Ward resolves to `rgb(46,116,158)` at 5.11:1, within a hair of the mock's hand-picked `#2b7fb0`, and NYC/SF palettes need no per-fork tuning.

**Two behaviors worth knowing when porting.** A hovered pin is the popup's *subject*, not a row: it takes a promoted header block, and its pill is read from its own layer's row rather than carried on the token, so the pin and the row beneath it cannot disagree. When the pin's layer has **no** polygon row — a station/library/post-office dot — there is nothing to anchor to, so the header block *is* the popup (10c) and the surrounding districts are left to the click cards. Districts shown for a pin are the pin's, not the cursor's; `updateHover` already anchored the stack at `poi.latlng`, so that needed no change.
