Stops the data-gaps panel telling a reader outside the covered area that nothing is missing where they clicked — outside the coverage, everything is. Found by a reader with a pin in Jo Daviess County: the only gray-washed county left on Chicago's northern edge answered "Nothing missing where you clicked." **Two changed blocks, no new blocks** — adopting forks need no fence seeding and nothing outside the fences.

- **Changed `scope-mask`**: the coverage outline rings the mask already dissolves for the gray wash are now RETAINED in a module-scope `coverageMaskRings` (null until the mask loads) instead of being discarded after drawing. No behavioural change to the wash itself; this is one assignment, placed after the existing dissolve-or-fallback logic so the retained rings are exactly what the wash drew.

- **Changed `coverage-gaps`**: a new `pointInCoverage(point)` tests the pin against those retained rings (even-odd across the flat ring list — `pointInGeometry` already handles outers-plus-holes this way), returning true / false / **null-for-unknown**. The section-header logic gains one honest branch: when no gap matched the pin AND the pin is outside the covered area, the header reads "Where you clicked is outside the covered area — the recorded gaps:" instead of "Nothing missing where you clicked — elsewhere:". The "nothing missing" wording now also **requires** `pointInCoverage === true` — it previously required only that some gap was mappable, which let an out-of-coverage pin claim a clean bill.

**Null fails safe, in both directions.** If the mask never loads (its fetch failed, or the panel opens before idle work runs), `pointInCoverage` returns null and the header falls back to the wording that claims neither — "Known gaps". A fork whose mask is absent entirely keeps exactly its current behaviour.

**Why the rings, not a coverage file.** The obvious design was a METRO constant naming a coverage-outline URL for the panel to fetch — and it would have required every sibling to add a variable outside the fence before the block could run, which a bump PR does not do (the v1.0.21 lesson, verbatim). The mask already receives each fork's coverage loader from BOOT and already dissolves the outline; reading what it computed costs nothing and cannot disagree with the wash the reader is looking at.

**The fork-data half is not in this release.** Chicago also shipped `<slug>-county-outline.json` files for three counties it does NOT serve (Jo Daviess, Bureau, Mercer) purely so their recorded gaps attach to their ground in the panel's "Where you clicked" section — that is fork data riding the existing slug contract, no engine involvement. A fork adopting this release gets the honest out-of-coverage header immediately; making an *unserved* county's gap locally visible additionally needs that fork to ship the county's outline and tag the gap with its slug.
