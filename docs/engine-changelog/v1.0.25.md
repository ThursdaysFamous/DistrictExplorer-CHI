Rewrites the Data gaps panel for the reader it was built for. **Three changed blocks (`coverage-gaps`, `gaps-modal-html`, `styles-footer`), no new blocks** — but this release changes the shape of `data/app/coverage-gaps.json`, so a fork that bumps without regenerating that file loses the panel's "Why" line. Read the adoption note before merging the bump.

**Why.** The panel printed the gap record's `blocker` field verbatim under a heading reading "Why". `blocker` is the maintainer's measured record — which host answered what, on which date, which route was proven closed — and on the harder counties it runs past ten thousand characters. Chicago shipped 111 gaps whose blockers totalled 238 KB, into a modal a voter opens to find out one thing: *is the answer I came for missing where I live?* The surface whose entire job is to make absence legible was the least legible thing in the app, and the reader had to scroll a research log to learn whether their own county was even mentioned. The record was never the problem; printing it at a voter was.

- **Data contract — `why` replaces `blocker` in the shipped file.** `scripts/build_coverage_gaps.py` now emits `summary`, `why` and `wanted` and does **not** emit `blocker`. All four fields remain required in the guidebook's `GUIDEBOOK:BEGIN gaps` block; `blocker` simply stays there, unbounded, for the next maintainer. The three reader fields are capped at **240 characters** each and linted for the four tells that a research note is leaking back into the panel — over budget, a hostname or URL, an ISO date, or a run of shouted capitals. Chicago's payload went 319 KB → 69 KB with no gap dropped.

- **Changed `coverage-gaps`**: one visible line per gap (`summary`), with `why` + `wanted` + the source-submission link moved into a per-gap `<details>`. Gaps are grouped into `<details class="gaps-group">` sections carrying their own counts — "Where you clicked" (open) first when a point is selected, then one group per kind. The kind vocabulary is now the reader's rather than the pipeline's: *not published* / *publisher blocks us* / *partly published* as badges, and full sentences as headings. A new `.gaps-lede` answers the reader's actual first question before the list — how many gaps affect the clicked point, or that none do, or that they clicked outside coverage entirely — with the same three provability guards the old section headings carried. Groups open by default only when a fork has 12 or fewer gaps to show, so a three-gap sibling never renders as a stack of closed drawers.

- **Changed `gaps-modal-html`**: intro copy rewritten to say what the panel is for in a voter's terms, and to point at the disclosure rather than dumping the reasoning inline.

- **Changed `styles-footer`**: `.gaps-lede`, `.gaps-group`, `.gaps-section-text` / `-count`, `.gap-more` / `.gap-more-label`, and disclosure-marker suppression on both summary elements. The old `.gaps-section-label` rule is kept and extended (it is now a `<summary>`), so nothing a fork styled disappears.

**Fork adoption — the bump alone is not enough.** Regenerate the fork's data file from Chicago's guidebook in the same PR:

```
python3 scripts/build_coverage_gaps.py --metro <fork> --out <fork>/data/app/coverage-gaps.json
```

A fork that authors its own `coverage-gaps.json` instead must add a `why` to every entry (and may drop `blocker` from the shipped file). Nothing breaks without it — a gap with no `why` renders its disclosure with only "What would fix it" — but the panel then explains half of what it used to. `fleet_status.py`'s GAPS check compares shipped file to guidebook and will report the difference either way.

**Smoke test worth porting alongside** (Chicago's is updated): assert that each rendered group's displayed count equals the items actually inside it, that the group items sum to the shipped gap count, and that every gap keeps its detail behind a disclosure — that last one is the assertion that fails if a research note ever grows back into the card body. The old assertion counted `.gaps-section-label` elements as siblings of `.gap-item`; sections are containers now, so a fork's copy needs the same rewrite whether or not it carries the rest.

**No generator output shape changed** — `generate_metro_files.py` emits exactly what it did, so bump PRs hit no `--check` drift.
