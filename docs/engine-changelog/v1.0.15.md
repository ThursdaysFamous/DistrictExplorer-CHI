Fences the hover popup to the map viewport, and fixes the card width v1.0.14 shipped clamped. Changed blocks only — **no new blocks, no fence-set change, no fork adoption required**.

- **Changed `hover-explorer`**: new `fenceHoverPopup(latlng)`, called at the end of `showHover`. It clamps the popup horizontally so it never runs off the left or right edge, flips it below the cursor when there isn't room above, and slides the tail back so it still points at the spot being read. `showHover` now resets the offset before each frame's measurement, so a correction never compounds across frames. New constants `HOVER_TIP` / `HOVER_EDGE` / `HOVER_TAIL_INSET` / `HOVER_TAIL_HALF` / `HOVER_WIDTH` / `HOVER_OFFSET_X` / `HOVER_OFFSET_Y`.
- **Changed `hover-explorer`**: the popup declares `maxWidth: HOVER_WIDTH` (324). **This is a v1.0.14 bug fix** — Leaflet's default `maxWidth` is 300 and it writes an inline `width` onto the content element, which beats the stylesheet, so the card rendered 24px narrower than the design everywhere. Measured 303px before, 327px (324 + padding + border) after.
- **Changed `styles-hover-responsive`**: `.hover-popup.hover-below .leaflet-popup-tip-container { top: -19px }` plus the tail's border flip, so a flipped popup's tail points up from its top edge.

**Why not `autoPan`.** Leaflet's built-in answer to an edge-crowded popup is to pan the map. That is exactly wrong here: the popup follows the cursor and describes the point under it, so panning would move the thing being inspected out from under the reader — and, because the popup re-anchors as the map moves, it would chase itself. `autoPan` stays `false`; the popup moves, the map never does.

**Why measured, not computed.** `fenceHoverPopup` reads the rendered box and corrects by the delta rather than deriving a position from the anchor. Leaflet's own placement already accounts for the tail strip, the zoom-animation path and the content size, so measuring stays correct even if any of those change; a formula would have to mirror Leaflet's internals and would rot against them. Both reads happen before the single write, so this costs one layout pass per frame, not one per adjustment. One consequence worth preserving when porting: the flipped state changes **only** the tail (absolutely positioned), never `.leaflet-popup`'s own margins — so the card's geometry is identical in both modes and a single measure-correct pass is sufficient. Swapping `margin-bottom` for `margin-top` would move the box between the measurement and the write.

**Flip hysteresis.** The popup flips below only when it does not fit above *and* there is more room below. Near the vertical middle of a short map both conditions would otherwise flicker as the cursor moves a pixel; requiring the second makes the choice stable.

Verified against a real Leaflet popup on the live map at six probe points (each corner, top-center, center): the box stays inside the map frame on all three clamped edges, the tail stays over the hovered point, the flip happens at the top edge only, and the card measures its design width.
