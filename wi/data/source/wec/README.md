# Wisconsin Elections Commission — polling-place file (build input)

`Polling Place Listing (3).xlsx` is the file the Commission sent this project
directly. It is committed here because **there is no URL to fetch it from.**
The Commission's Jodi Vitcenda wrote, 2026-08-27 (help-desk ticket 123582):

> The list ... is posted on the elections.wi.gov/elections portion of the site
> ... I can't provide any direct links for the attachments at this time, as it
> isn't published there for November yet, but that is where it would be.

So the file is **provisional**: it is the Commission's working list for the
3 November 2026 General Election, months before the published edition. Every
card built from it says so in the reader's own sentence, and
`wi/scripts/build_wi_polling_places.py` carries the whole arrangement.

**Re-pull on 17 September 2026** (`wi/WATCH.md`): that is the statutory
deadline by which municipal clerks must have published their polling places
for the November election, and the Commission's own published file should
exist at `elections.wi.gov/elections` from about then. Replace this file,
rebuild, and clear the provisional flag.

## What is deliberately NOT here

The same reply attached `In-Person Absentee Voting Locations (1).xlsx`. It is
**not committed and not shipped**, for two measured reasons:

1. **It is not a statewide answer.** It carries 34 municipalities out of
   Wisconsin's 1,846 — 1.8% — and its own first line says so: "This list is
   not an exhaustive list, clerks are not required to share with the WEC the
   locations and times they offer In-Person Absentee Voting." A card built on
   it would tell a reader in Madison that Madison has no early voting.
2. **Two of the 34 entries are a clerk's private home** ("... Town Clerk's
   Home", "... Village Deputy Clerk's Home", both at the same residential
   address). The Commission may publish that; mirroring it into a public git
   repository indefinitely is a different act, and this project does not make
   it.

The measurement is recorded in `docs/DATA_LAYER_GUIDEBOOK.md` instead, which
is what a gap record is for.

## Privacy check on what IS here

The polling file's 3,623 rows carry no residential address. 141 rows are typed
`Private`, which means a privately **owned** building — senior centres, clubs,
museums, a Masonic centre — not a residence; the only row whose name even
contains "residence" is St. Camillus Independent Living West in Wauwatosa, a
public-access retirement community. Re-run that check on any replacement file.

# Wisconsin Elections Commission — municipal clerk directory (build input)

`WI Municipal Clerks Updated 8-4-2026.pdf` came from the same reply, and it is
committed here for a **different reason** than the polling file. This one *is*
published — Jodi Vitcenda, 2026-08-27:

> here is the clerk list, also provided as pdfs on the site … Here is that url
> for the future: https://elections.wi.gov/clerks/directory

So a fetchable original exists and **this project still cannot fetch it.** The
Commission's front page clears a real browser, and every interior `/clerks/*`
path re-challenges the same cleared session — measured over 17 interior page
attempts in two CI runs (`wi-wec-recon.yml` runs 33035225999 and 33036310501;
the record is the `municipal-officers` gap's blocker). The Zendesk attachment
token this copy came from is per-ticket and will rot. Hence a committed file,
dated, with the published URL recorded as the thing to re-pull from when it
becomes reachable.

Generated by Microsoft Reporting Services 2022, 8/4/2026 1:43 PM, 395 pages,
1,848 municipalities. `wi/scripts/build_wi_municipal_clerks.py` carries the
parse and the gates.

## THERE ARE NO E-MAIL ADDRESSES, AND THAT IS THE CLERKS' OWN CHOICE

The PDF's `/Subject` metadata says it outright — `WI Municipal Clerks PDF - no
emails:` — and the Commission confirmed why when asked:

> Yes, the list for muni clerks does not have email addresses provided, I
> believe that was at their request.

The county-clerk file in the same reply *does* carry them. So the absence is a
withholding by the people named, not an oversight to route around, and nothing
in this build goes looking for those addresses on another surface to backfill
them. Measured: 0 of 1,848 records contain `@`.

## NO ADDRESS SHIPS, AND THIS IS THE MEASUREMENT BEHIND IT

Every record carries `Municipal Address` and `Mailing Address`. **The file has
no field distinguishing a village hall from the clerk's own house, and it
demonstrably contains both.** The proof does not require guessing at any one
address — it comes from clerks who serve more than one municipality:

| Clerk | One address, filed under | 
|---|---|
| Amber Larson | Towns of Hoard, Grover, Holway **and** Maplehurst |
| Lori Opitz | Town of Oconomowoc **and Village of Lac La Belle** |
| Tom Monacelli | Town of Warren **and Village of Lohrville** |
| Wendy Burnette | Town of Somers and Village of Somers (a PO box) |

Four municipalities cannot share one municipal building. Where the same street
address is filed under two of them it is the person's, and two of those cases
reach a **village** — that is, the City or Village card this build feeds. A
further 27 city/village records give a mailing street different from the
municipal street with no PO box, each of which may be a residence and none of
which can be told apart from a village hall by any published field.

So the builder never reads either address label. That is deliberate and
stronger than dropping them at the end: a field that is never extracted cannot
leak into an output. **Do not add them back.** The standing rule is that home
addresses never ship, and here the file cannot say which ones they are.

What does ship: the clerk's name, the deputy clerk's name where the file gives
one, `Phone 1`, the municipality's own website, and the record's **own
last-updated date** — which ranges from 2023 to 2026 and is per record, so the
card dates each answer rather than implying the whole file is current.

## Re-pull

Same posture as the polling file, different trigger: this one has no election
date attached, so it is re-pulled when the Commission's own page becomes
