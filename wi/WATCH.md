# WATCH.md — redistricting watch calendar

The one place the dates live: *when to look* for boundary and roster changes in this
instance's sources. The repo's `docs/REDISTRICTING_RUNBOOK.md` is *what to do* when a
boundary changes. Update the "Last done" column each time you complete a row — a
checkpoint with a stale date is a checkpoint that didn't happen.

---

## Semiannual — the county supervisory filing windows

| When | What | Last done |
|---|---|---|
| Shortly after **15 January** and **15 July** | Wis. Stat. 5.15(4)(br)1 makes every county file its current supervisory district boundaries with LTSB on those two dates, and LTSB republishes the statewide layer. Re-run `wi/scripts/build_wi_supervisory_districts.py`: its gates (1,589 LTSB features raw — the SHIPPED file is 1,590, −16 LTSB Trempealeau +17 from the county's own service — 72 counties, 1..n numbering per county, ward reconciliation) are what catch a county whose plan changed or whose filing broke. A count change is expected news, not a failure — read it, then move the expected number | 2026-08-25 (July 2026 filing; 1,590 districts shipped) |
| Same windows | **The aldermanic dissolve rides the same filings**: re-run `wi/scripts/build_wi_aldermanic_districts.py`. Its gates (2,580 coded wards, 867 statewide keys, the pinned ten-municipality exclusion list, four pinned sliver holes, the BAS pre-dissolve witness, ≥99.9% point agreement) each catch a different way a filing can move — and the EXCLUDED list is the one to hope changes: a county completing Appleton's (or any of the ten's) ward coding is how a city leaves the `aldermanic-incomplete-filings` gap. Bump the sw cache when the geometry file changes | 2026-08-26 (July 2026 filing; 838 districts, 155 municipalities shipped) |
| Same run | Re-check **Trempealeau**, the one county whose geometry comes from its own service rather than LTSB's. If a future LTSB filing restores its district 15, drop the override and ship the statewide file whole — the builder will tell you, because the override's own guards fail if the county's layer stops publishing 17 districts numbered 1..17 | 2026-08-25 (LTSB still merges 15 into 17) |
| Odd-year January | **The legislature's biennium path**: wi_legislature_scraper.py reads docs.legis.wisconsin.gov/<biennium>/legislators/… and the unversioned path 404s, so the BIENNIUM constant must be bumped (2025 → 2027 → …) or the office enrichment silently reads a frozen session. The scraper's floors catch a page reshape; only this calendar row catches the frozen path | 2026-08-25 (2025-26 biennium; offices shipped 132/132) |
| November, even years | **County clerks** elect on the fall partisan ballot (Wis. Stat. 7.20); appointments fill vacancies year-round and arrive as roster-PR diffs from the weekly two-source scrape. The BIENNIAL drift is the Blue Book itself: the 2027-28 edition will publish under a new docs.legis path, and wi_county_clerk_scraper.py's URL follows it BY HAND — the monthly source report warns when the old excerpt goes stale. **The OTHER county officers (phase 4)** — sheriff, DA, treasurer, clerk of circuit court, register of deeds, chair, executive, coroner/ME — ship from the same book's officer tables DATED to its April 2025 snapshot, and turn over on the same partisan ballots (DAs in presidential years, most others in midterms): the honest refresh for them IS the next Blue Book edition, so the biennium bump is when their currency actually moves. The builder's chair-seats witness (against the shipped supervisory geometry) and the Menominee 7-vs-5 pin re-measure on every weekly run | 2026-08-26 (officers shipped: 72 counties x 7 offices; 12 elected county executives, 45 medical examiners, Dunn's manager, Richland's uncoded administrator; Menominee pinned) |
| Spring elections (April) | **Court of Appeals judgeships** elect one per district per year at most (Wis. Stat. 752.03), staggered six-year terms — the weekly wicourts scrape carries turnover as a roster-PR diff. A FAILED run means a seat count moved off 4/4/3/5 (a vacancy — read it) or the district composition itself changed (752.11 — rebuild the geometry in the same change) | 2026-08-25 (layer shipped; 16 judges) |
| Spring elections (April, odd and even years) | **Circuit judgeships** elect every April on staggered six-year terms, and vacancies fill by appointment year-round — the weekly wicourts scrape carries both without ceremony (a new name is a diff on the roster PR). What deserves a read is a FAILED weekly run: the scrape asserts the statutory circuit composition (Wis. Stat. 753.06 — the three two-county circuits), so a failure can mean the circuit map itself moved, which needs `wi/scripts/build_wi_circuit_courts.py` re-run in the same change | 2026-08-25 (layer shipped; 261 judges, 234 with direct phones) |
| USGS republication (roughly annual, unannounced) | The **police-station / fire-station / post-office** layers all ride the USGS National Map structures service live, which is republished wholesale without a schedule. Nothing to rebuild — the monthly source report's envelope returnCountOnly rows are where a count change (or the service going dark) surfaces. The known data caveat travels with the source: ghost records happen (a fire department defunct since 2020 is the verified example), which is why the cards present proximity and never a service claim | 2026-08-25 (July 2026 republication; 807 police / 1,743 fire / 1,244 post offices in the envelope) |
| Around each school year (late summer) and the annual library-system data (spring) | The **school-site / library** layers are PRE-BUILT from DPI's own AGO org, which rotates the school directory around each school year and refreshes the library directory from the annual public library system data. Re-run `wi/scripts/build_wi_school_sites.py` and `build_wi_libraries.py`, read the diff, ship it as a PR — the builders' gates (paging asserted against the layer's own count, the placeless-virtual-program skip, the mercator-meters LAT/LONG trap, state-bbox and floor checks) are what catch a rotation that changed shape rather than content. The monthly source report also watches DPI's catalog item (d383fe81275e46f2a5a5c4f1a0c2eb85) for the successor-item pattern | 2026-08-26 (initial build: 2,966 school sites — 2,138 public + 828 private, 152 placeless virtual rows skipped — and 482 library outlets, 481 with phones) |
| Unscheduled — the city republishes when the facts move | The **Milwaukee city quartet** (`mpd-district`, `mpd-squad-area`, `milwaukee-neighborhoods`, `tid-district`) is PRE-BUILT by `wi/scripts/build_milwaukee_city_layers.py` from city surfaces that change without a calendar: MPD redraws districts and squads when it reorganizes (not on the census cycle), the neighborhood map moves rarely if ever, and TIDs are CREATED AND CLOSED by Common Council action — the 79 will move, and the exact worksheet count moves with the rebuild. Nothing weekly to review — the monthly source report watches the ArcGIS doors and CKAN dataset pages, and a count or reachability change there is the trigger to re-run the builder, read the diff, and bump the sw cache. The builder's witnesses (exact key sets 1-7 / 25 / 190, area shares within 0.5%, the space-folded neighborhood key, and each squad sample-verified inside its hundreds-digit district) are what catch a republication that changed shape rather than content — an MPD redraw that breaks the hundreds-digit rule fails the squad gate loudly | 2026-08-26 (first build: 7 districts at 0.04% max share difference, 25 squads at 0.02% all verified in-district, 190 neighborhoods at 0.007% — one spelling divergence on the record) |
| Unscheduled — the OEC refreshes roughly weekly | The **NG911 quartet** (`fire-service`, `law-service`, `ems-service`, `psap-area`) is PRE-BUILT by `wi/scripts/build_wi_ng911_service_areas.py` from the OEC's statewide aggregate, which republishes as counties file — no calendar. The monthly source report's four returnCountOnly rows are the trigger: a count change is a county filing (expected news — re-run the builder, read the diff, move the worksheet's exact feature counts and bump the sw cache), and the UNFILED gate failing is the GOOD news this row exists for: a dark county (Iowa, Langlade, Vilas, Walworth, Jefferson's fire+EMS, Polk's partial law) completed its filing, so retire its entry from UNFILED and from gaps `ng911-fire-filings` / `ng911-law-filings` / `ng911-psap-filings` / `ng911-ems-filings` together. PSAP's future-dated Expire rows (11 at first build) mean its counts can also move when a dated filing simply expires — the drop-by-date rule handles it, but read the diff | 2026-08-26 (first build: 1,046 fire + 639 law + 579 EMS + 95 PSAP areas, all at 100.000% name-set agreement; 5 authorities pinned absent/partial, Langlade provisioning-less) |
| Same windows | The **ward layer** rides the same filings LIVE — no rebuild to run, because both its point query and its paged overlay hit LTSB's Current service directly. What to do instead: read the count off the monthly source report (the returnCountOnly ENDPOINTS row) and treat a change as expected news (Jan 2026 filed 7,138, July 2026 filed 7,161 — the same total as July 2025, a verified coincidence); it is the layer going unreachable or answering zero that is a failure. The supervisory builder's ward-reconciliation gate independently re-witnesses the ward↔district pairing on its own re-run | 2026-08-25 (layer shipped against the July 2026 filing) |

## Per-election — the seats above the boundaries

| When | What | Last done |
|---|---|---|
| After each Wisconsin general (November, even years) and any special election | The chamber rosters turn over; the weekly Open States refresh picks it up, but verify the first post-election PR against the Legislature's own directory before merging | 2026-08-25 (initial build: 33/33 + 99/99) |
| After each **spring election (April)** | **MPS school board directors** elect on staggered four-year terms (the shipped roster's expirations run April 2027 and April 2029), and the weekly scrape carries turnover with the committee-list witness. The GEOMETRY moves once a decade: the districts were adopted 2022-02-25 after the 2020 census, so re-run `wi/scripts/build_mps_school_board_districts.py` after the post-2030 reapportionment — its CKAN-shapefile witness fails loudly if the two city surfaces ever disagree mid-decade | 2026-08-26 (first build: 9 directors, all with terms; area shares witnessed at 0.04% max difference) |
| After each **spring election (April, even years — and odd years for the cities that stagger)** | **Alderpersons** in the six rostered cities elect at spring elections, and the weekly scrape carries turnover — but the Kenosha witness pins THIS canvass: after each spring election, point `KENOSHA_CANVASS` in `wi_alderperson_scraper.py` at the county's new certified results document and re-verify, and re-read any `KENOSHA_CANVASS_WINS` pin (each is self-retiring — the build fails the day the GIS catches up). Madison's vacant-seat list changes at elections and appointments; the per-district pages carry it without ceremony | 2026-08-26 (first build: 93 named + Madison D1 vacant; Kenosha D14 ships the certified April 2026 winner over the stale GIS) |
| After each **spring election (April, even years)** | County supervisors are elected to two-year terms then, so the 22 shipped rosters turn over at once. The weekly run picks it up, but verify the first post-seating PR against a couple of counties' own pages before merging — this is also when counties reorganise their board pages, which is what breaks the pinned reading direction. The two county-GIS rosters (Milwaukee, Racine) need their layers' own edit dates re-checked PAST the election before names ship — Milwaukee's Legistar witness fails the county loudly if the layer lags | 2026-08-26 (22 counties, 476 seats: 474 named, 2 vacant; Milwaukee + Racine joined off their own GIS) |

## Per-decade — the census redistricting cycle

| When | What | Last done |
|---|---|---|
| After each decennial census (next: 2031–2032) | Congressional + legislative districts redraw: re-run `wi/scripts/build_legislative_boundaries.py` (all three targets), confirm the district counts against the apportioned delegation and the 33/99 chambers, and re-verify the smoke anchors against the rebuilt geometry | 2026-08-25 (chambers built at 100.00% agreement) |
| Mid-decade — Wisconsin specifically | Wisconsin's legislative maps have moved OFF-cycle before (the 2024 remap after Clarke v. WEC). A chamber-map change outside the census cycle is plausible here in a way it isn't in most states: any news of a court-ordered remap means re-running the chamber builds and anchors without waiting for the decade | _(watching)_ |
| Same cycle | County subdivisions / places / school districts shift in TIGERweb continuously; the live layers pick changes up on their own, but the PRE-BUILT files (`state-counties.json`, `school-districts-unified.json`) need a rebuild | _(never)_ |

## Grow this file

Every new layer ships with a row here naming when its source moves (school-year datasets
rotate every summer; county precinct files change per election; rosters change per election
and per resignation). A source with no row is a source nobody is watching.
